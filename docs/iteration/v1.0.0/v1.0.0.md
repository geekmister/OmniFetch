# v1.0.0 迭代文档



## 事件一

检查当前项目架构是否是使用`Electron Vite`构建，参考模板是`electron-vite-vue`（Github：https://electron-vite.github.io/），如果不是，需要迁移成`Electron Vite`构建。

### 迁移改造方案

#### 1. 现状诊断（结论：非 Electron Vite 构建）

当前项目基于社区插件 `vite-plugin-electron` + `vite-plugin-electron-renderer` 搭建，与官方 `electron-vite-vue` 模板存在以下差异：

| 维度 | `electron-vite-vue`（目标） | 当前项目 | 是否一致 |
|------|------------------------------|----------|----------|
| 核心依赖 | `electron-vite` | `vite-plugin-electron` / `vite-plugin-electron-renderer` | ❌ |
| 配置文件 | `electron.vite.config.ts`（main/preload/renderer 三段） | 单一 `vite.config.ts` 手动挂插件 | ❌ |
| 启动脚本 | `electron-vite dev` | `vite` + `electron .` 分离 | ❌ |
| 构建脚本 | `electron-vite build` | `vite build` + `electron-builder` | ❌ |
| preload 处理 | 原生支持 TS 编译 | 额外写 `copy-preload-cjs` 插件拷贝 `preload.cjs` 绕过 ESM | ❌ |
| 目录结构 | `electron/{main,preload,renderer}` 分离 | `electron/` 混放 `main.ts`/`preload.ts`/`preload.cjs` | ⚠️ |

> 证据：`package.json` 的 `devDependencies` 无 `electron-vite`；全仓库无 `electron.vite.config.ts`；`vite.config.ts` 通过 `electron([{ entry: 'electron/main.ts' }])` 手动挂载。

#### 2. 迁移目标

将构建体系从 `vite-plugin-electron` 平滑迁移到官方 `electron-vite`，消除 `preload.cjs` 拷贝 hack，统一为声明式三段配置，保持现有功能（yt-dlp 调用、IPC 通信、二进制路径解析）不变。

#### 3. 实施步骤

**步骤 1：依赖调整**
- 安装：`npm i -D electron-vite`
- 移除：`npm un vite-plugin-electron vite-plugin-electron-renderer`
- 保留：`vite`、`@vitejs/plugin-vue`、`vue-tsc`、`electron-builder`、`typescript`

**步骤 2：新增 `electron.vite.config.ts`（替换 `vite.config.ts`）**

```ts
import { defineConfig } from 'electron-vite'
import vue from '@vitejs/plugin-vue'
import { resolve } from 'path'

export default defineConfig({
  main: {
    build: {
      rollupOptions: {
        external: ['electron'],
      },
    },
  },
  preload: {
    // electron-vite 原生编译 TS preload，无需 .cjs 拷贝 hack
  },
  renderer: {
    resolve: {
      alias: {
        '@': resolve('src'),
      },
    },
    plugins: [vue()],
  },
})
```

**步骤 3：清理 preload 拷贝 hack**
- 删除 `electron/preload.cjs` 及 `vite.config.ts` 中的 `copy-preload-cjs` 插件。
- 将 `electron/main.ts` 中 `preload: join(__dirname, 'preload.cjs')` 改为 `preload: join(__dirname, '../preload/index.js')`（由 electron-vite 输出）。

**步骤 4：规范 `electron/` 目录结构**

```
electron/
├── main/
│   └── index.ts        # 原 main.ts（BrowserWindow + ipcMain）
├── preload/
│   └── index.ts        # 原 preload.ts（contextBridge 暴露 electronAPI）
├── downloader.ts       # 保持不变
├── bin-resolver.ts     # 保持不变
└── ytdlp-updater.ts    # 保持不变
```

> `downloader.ts` / `bin-resolver.ts` / `ytdlp-updater.ts` 为共享模块，可保留在 `electron/` 根目录或移入 `electron/shared/`，main 与 preload 按需 import。

**步骤 5：更新 `package.json` 脚本**

```json
{
  "scripts": {
    "dev": "electron-vite dev",
    "build": "electron-vite build",
    "preview": "electron-vite preview",
    "download:bins": "node scripts/download-bins.mjs",
    "electron:build": "npm run download:bins && electron-vite build && electron-builder"
  }
}
```

> 移除原 `vue-tsc --noEmit && vite build` 中的 `vite build`（改由 `electron-vite build` 统一处理 renderer 类型检查与构建）；类型检查可保留在 CI 门禁中单独执行 `vue-tsc --noEmit`。

**步骤 6：对齐 `tsconfig`**
- 保留 `tsconfig.json`（renderer）+ `tsconfig.node.json`，新增 `tsconfig.main.json` 与 `tsconfig.preload.json`（参考 `electron-vite-vue` 模板），并在根 `tsconfig.json` 的 `references` 中引用。
- 确保 `electron/main/index.ts` 与 `electron/preload/index.ts` 的 `include` 覆盖到位。

#### 4. 风险与权衡

- **preload 路径变化**：`main.ts` 中 `preload` 路径需随 electron-vite 输出目录调整，否则打包后白屏。
- **`__dirname` 兼容**：electron-vite 的 main/preload 默认编译为 CJS，原 `main.ts` 中 `import.meta.url` 写法需改为 `require` 风格或确认编译产物格式；建议统一使用 `__dirname`（CJS 输出）以避免 ESM 路径问题。
- **`extraResources` 不变**：`bin/` 目录仍通过 `electron-builder` 的 `extraResources` 拷贝，迁移不影响二进制资源加载逻辑。
- **回滚方案**：保留 `vite.config.ts` 备份，若 electron-vite 构建异常可临时切回 `vite-plugin-electron`。

#### 5. 验收标准

- [ ] `npm run dev` 等价于原 `vite` + `electron .`，窗口正常加载、yt-dlp 功能可用。
- [ ] `npm run electron:build` 产出可安装包，二进制 `bin/` 正确打包。
- [ ] 仓库中无 `preload.cjs` 及 `copy-preload-cjs` 插件残留。
- [ ] 存在 `electron.vite.config.ts`，`package.json` 依赖含 `electron-vite`、不含 `vite-plugin-electron`。
- [ ] `vue-tsc --noEmit` 类型检查通过（CI 门禁）。



## 事件二 

迁移 `Tailwind + lucide-vue-next + 自定义 CSS 组件类` → `TDesign Vue Next`，保持现有功能与交互逻辑不变。

> **现状诊断（前提纠正）**：经全仓库核查，当前**并非** `Tailwind + Primer`。实际技术栈为：
> - `tailwindcss@^3.4.0`（仅用于 `@apply` 抽取自定义组件类）
> - `lucide-vue-next@^0.300.0`（全部图标来源）
> - **自定义 CSS 组件类**：`src/style.css` 中手写 `.btn-primary` / `.btn-secondary` / `.btn-danger` / `.input-field` / `.card` 等，配合 `tailwind.config.js` 自定义暗色主题色板（`surface` / `accent` / `text` / `danger` 等）
> - 全仓库无任何 `@primer/*` 依赖或 import（搜索 `primer` 仅命中本文档自身）
>
> 因此迁移起点是「**Tailwind + lucide-vue-next 图标 + 自定义 CSS 组件类**」，目标替换为 `TDesign Vue Next`（`tdesign-vue-next` + `tdesign-icons-vue-next`）。

要求：

1、尽量采用 TDesign 原生默认组件和样式；
2、移除 Tailwind 及自定义 CSS 组件类，统一由 TDesign 主题与组件承载视觉；
3、保留现有暗色视觉风格（通过 TDesign 暗色模式 `t-theme-dark` 实现，而非自定义色板）；
4、图标统一切换为 `tdesign-icons-vue-next`，不再依赖 `lucide-vue-next`；
5、保持现有功能与交互逻辑（URL 解析、格式选择、下载进度、暂停/继续/取消）完全不变。

### 迁移方案

#### 1. 组件映射表（现有 → TDesign 原生）

| 现有实现 | TDesign 原生组件 | 说明 |
|----------|------------------|------|
| `.btn-primary`（解析 / 开始下载） | `<t-button theme="primary">` | 品牌色填充按钮 |
| `.btn-secondary`（暂停 / 继续） | `<t-button theme="default">` | 默认填充按钮 |
| `.btn-danger`（取消） | `<t-button theme="danger" variant="outline">` | 危险色线框按钮 |
| `.input-field`（URL 输入） | `<t-input>` + `prefixIcon` | 用 `LinkIcon` 作前置图标 |
| `.card`（视频信息 / 格式 / 进度容器） | `<t-card bordered>` | 去掉自定义标题时用无 `title` 卡片 |
| 格式列表选中态（手写 button + 高亮） | `<t-check-tag v-model:checked>` | 单选格式用受控 `checked` 绑定 |
| 进度条（手写 div 宽度） | `<t-progress theme="line" :percentage :status>` | `status` 映射：下载中 `active` / 暂停 `warning` / 完成 `success` |
| 解析中加载（手写 spinner + 文案） | `<t-loading text="正在解析视频信息...">` | 或 `<t-button :loading>` |
| 解析错误 / 下载错误（手写 danger 卡片） | `<t-alert theme="error" :title>` | 内联错误提示 |
| 状态小图标（完成/暂停/下载中圆形标） | `<t-progress>` 状态 + `tdesign-icons` | 圆形标可用 `CheckCircleIcon` / `PauseCircleIcon` / `LoadingIcon` |
| 免责声明页脚 | 纯文本（`<t-typography>` 可选） | 保持 `select-none` 弱化处理 |

#### 2. 图标映射表（lucide → tdesign-icons-vue-next）

| lucide 图标 | TDesign 图标 |
|-------------|---------------|
| `Link` | `LinkIcon` |
| `Download` | `DownloadIcon` |
| `Pause` | `PauseIcon` |
| `Play` | `PlayCircleIcon` |
| `X` | `CloseIcon` |
| `Check` | `CheckIcon` / `CheckCircleIcon` |
| `AlertCircle` | `ErrorCircleIcon` |
| `Loader2`（spin） | `LoadingIcon`（自带旋转） |
| `Film` | `FilmIcon`（缩略图占位）/ `VideoIcon`（格式计数） |
| `Clock` | `TimeIcon` |
| `FileVideo` | `VideoIcon`（TDesign 无 FileVideoIcon，统一用 VideoIcon） |
| `Gauge` | `ChartIcon`（TDesign 无 GaugeIcon，速度用 ChartIcon 代替） |
| `Timer` | `TimeIcon` |

#### 3. 实施步骤

**步骤 1：依赖调整**
- 安装：`npm i tdesign-vue-next tdesign-icons-vue-next`
- 移除：`npm un tailwindcss postcss autoprefixer lucide-vue-next`
- 保留：`vue` / `pinia` / `electron-vite` 等（见事件一）

**步骤 2：注册 TDesign 并启用暗色（`src/main.ts`）**

```ts
import { createApp } from 'vue'
import { createPinia } from 'pinia'
import TDesign from 'tdesign-vue-next'
import 'tdesign-vue-next/es/style/index.css'
import App from './App.vue'
// 暗色样式（按需引入，配合根节点 t-theme-dark 生效）
import 'tdesign-vue-next/es/style/index-dark.css'
import './style.css'

const app = createApp(App)
app.use(createPinia())
app.use(TDesign)
app.mount('#app')
```

> 暗色模式通过在根容器（如 `App.vue` 最外层 `div` 或 `body`）添加类名 `t-theme-dark` 启用；`ConfigProvider` 仅用于语言/全局文案配置，不负责主题切换。

**步骤 3：清理 Tailwind 残留**
- 删除 `tailwind.config.js`、`postcss.config.js`。
- 重写 `src/style.css`：移除 `@tailwind` 指令与 `@layer` 自定义组件类，仅保留全局基础重置与拖拽区样式（`.drag-region` / `.no-drag` 为 Electron 标题栏所需，必须保留）：

```css
* { margin: 0; padding: 0; box-sizing: border-box; }
html { -webkit-font-smoothing: antialiased; -moz-osx-font-smoothing: grayscale; }
body { overflow: hidden; }
.drag-region { -webkit-app-region: drag; }
.no-drag { -webkit-app-region: no-drag; }
```

- 从 `package.json` 移除 `tailwindcss` / `postcss` / `autoprefixer` 及 `devDependencies` 中相关项。

**步骤 4：组件改造（逐文件）**

- `src/App.vue`：根 `div` 加 `class="t-theme-dark"`；标题栏 Logo + 名称保留，红绿灯留白区保留；主内容区用 `<t-layout>` / `<t-content>` 包裹（或直接保留 flex 布局，仅去掉 Tailwind 类，改用 TDesign 间距或内联样式）。
- `src/views/HomeView.vue`：错误块改用 `<t-alert theme="error">`；解析中改用 `<t-loading text="正在解析视频信息...">`；其余子组件引用不变。
- `src/components/UrlInput.vue`：`<input>` → `<t-input v-model="localUrl" :prefix-icon="LinkIcon" placeholder="..." @enter="handleSubmit" :disabled="store.isParsing">`；解析按钮 → `<t-button theme="primary" :disabled="!store.isValidUrl || store.isParsing" @click="handleSubmit">解析</t-button>`。
- `src/components/FormatSelect.vue`：外层 `.card` → `<t-card bordered>`；格式列表项 → `<t-check-tag v-model:checked="selected" :value="fmt.formatId">`，选中态由 TDesign 原生样式承载；分辨率标识 `<span>` → `<t-tag :theme="fmt.resolution === '音频' ? 'warning' : 'primary'" variant="light">`；缩略图 `<img>` → `<t-image>`（或保留原生 `img`，非强制）；图标 `Film/Clock/FileVideo/Check` → 对应 TDesign 图标。
- `src/components/DownloadButton.vue`：开始下载 → `<t-button theme="primary" block :disabled="!store.selectedFormat" @click="store.startDownload()">`；暂停/继续 → `<t-button theme="default" @click="...">`；取消 → `<t-button theme="danger" variant="outline" @click="store.cancelDownload()">`；图标 `Download/Pause/Play/X` → TDesign 图标。
- `src/components/DownloadProgress.vue`：进度条 → `<t-progress theme="line" :percentage="Math.round(store.progress)" :status="store.downloadComplete ? 'success' : store.isPaused ? 'warning' : 'active'">`；状态圆形标改用 `CheckCircleIcon` / `PauseCircleIcon` / `LoadingIcon`；速度/ETA 用 `GaugeIcon` / `TimeIcon`；外层 `.card` → `<t-card bordered>`。

**步骤 5：图标统一替换**
- 所有 `.vue` 中 `import { ... } from 'lucide-vue-next'` 改为 `import { ...Icon } from 'tdesign-icons-vue-next'`，并同步模板中的组件标签名（如 `<AlertCircle>` → `<error-circle-icon />` 或 `<ErrorCircleIcon>`）。

**步骤 6：类型检查与构建**
- 运行 `npm run typecheck`（`vue-tsc --noEmit`）确认 TDesign 类型无误。
- 运行 `npm run dev` 验证窗口加载、暗色主题、各组件渲染与 yt-dlp 功能。

#### 4. 风险与权衡

- **暗色色板差异**：TDesign 暗色默认色值与现有自定义 `surface(#0d1117)` / `accent(#58a6ff)` 不完全一致，视觉会有细微偏移；若需像素级还原，可在 `ConfigProvider` 的 `globalConfig` 中覆盖 CSS 变量（如 `--td-brand-color`），但优先采用 TDesign 原生暗色。
- **`<t-card>` 语义**：现有 `.card` 是纯容器，TDesign `Card` 默认带边框且设计间距不同，需通过 `bordered` / 内联 `style` 微调以贴近原布局。
- **`t-check-tag` 单选**：原生 `CheckTag` 为独立选中态，需手动保证「同一时刻仅一个 format 选中」（当前 store 已用 `selectedFormat` 单值承载，逻辑不变）。
- **包体增大**：引入完整 `tdesign-vue-next` 会增加渲染进程体积；若后续关注体积，可改为按需引入（`tdesign-vue-next/es/button` 等），但首版以「原生默认、全量引入」优先满足要求 1。
- **回滚方案**：保留 `tailwind.config.js` 与 `style.css` 旧版本备份，若 TDesign 暗色或布局异常可临时切回 Tailwind。

#### 5. 验收标准

- [ ] `package.json` 依赖含 `tdesign-vue-next` / `tdesign-icons-vue-next`，不含 `tailwindcss` / `postcss` / `autoprefixer` / `lucide-vue-next`。
- [ ] 仓库中无 `tailwind.config.js` / `postcss.config.js`，`src/style.css` 无 `@tailwind` 与自定义组件类（仅保留重置与拖拽区样式）。
- [ ] 应用以 TDesign 暗色模式（`t-theme-dark`）呈现，视觉风格与原暗色方案一致。
- [ ] 所有按钮、输入框、卡片、进度条、标签、错误提示均使用 TDesign 原生组件，无手写 Tailwind class。
- [ ] 图标全部来自 `tdesign-icons-vue-next`，无 `lucide-vue-next` 残留。
- [ ] `npm run typecheck` 通过；`npm run dev` 下 URL 解析、格式选择、下载进度、暂停/继续/取消功能正常。
